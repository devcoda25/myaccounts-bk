## 2024-03-01 - PostgreSQL In-Memory Sorts Avoidance via Composite Indexes
**Learning:** In Prisma with PostgreSQL, B-Tree composite indexes naturally support `ORDER BY ... DESC` queries without needing an explicit `sort: Desc` declaration. Prisma does not automatically index foreign key columns (like `userId` or `childId`). Therefore, access patterns involving filtering by a foreign key and sorting by a timestamp require composite indexes (e.g., `@@index([childId, at])` or `@@index([userId, createdAt])`) to prevent expensive in-memory sorts.
**Action:** When creating models that represent chronological logs, activities, or relational data frequently queried by owner/parent ID and ordered by time, always proactively add a composite index on `[foreignKey, timestampField]` in `schema.prisma`.
