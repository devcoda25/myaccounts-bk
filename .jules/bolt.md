## 2025-03-20 - [Backend] Add composite indexes for common filter/sort queries
**Learning:** In the codebase, it is a common access pattern to filter rows by a foreign key (e.g., `userId`, `childId`) and sort them by a timestamp (e.g., `createdAt`, `at`, `lastUsedAt`). Prisma and PostgreSQL do not automatically index foreign keys, and sorting operations can become very expensive as tables grow, leading to "filesort" or full table scans. Composite B-Tree indexes naturally support `ORDER BY ... DESC` without extra schema definitions.
**Action:** Always check the query patterns (especially those with `orderBy: { <timestamp>: 'desc' }`) and ensure the corresponding composite index (e.g., `@@index([foreignKeyId, timestampField])`) is added to `prisma/schema.prisma` to optimize sorting and filtering simultaneously. Verify fields exist in the model before adding.
