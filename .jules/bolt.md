## 2026-04-05 - Missing Chronological Access Pattern Indexes
**Learning:** Common queries across the application filter by a parent or user ID and sort chronologically (e.g., `findManyByChildId` with `orderBy: { at: 'desc' }` on ParentalActivity and `findUserTickets` with `orderBy: { createdAt: 'desc' }` on SupportTicket). Without composite indexes covering both the foreign key and the sort column (e.g., `@@index([childId, at])`), PostgreSQL resorts to expensive in-memory filesorts for these queries, becoming a significant bottleneck as data grows.
**Action:** Always explicitly check for and add composite indexes on Foreign Keys paired with sort columns (e.g., `createdAt`, `at`, `lastUsedAt`) in `prisma/schema.prisma` when adding models with chronological list access patterns.
