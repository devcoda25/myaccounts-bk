## 2025-02-23 - Prisma PostgreSQL Composite Indexing for In-Memory Sorts
**Learning:** Prisma with PostgreSQL requires explicit manual `@@index` definitions for composite fields used in sorting operations (e.g., `orderBy` in `findMany` queries). Failing to do so forces PostgreSQL to perform expensive in-memory sorts for common queries like fetching the latest records for a specific foreign key (e.g., `orderBy: { createdAt: 'desc' }` filtered by `userId`). Composite indexes natively support descending sorts without additional syntax in Prisma.
**Action:** When creating or analyzing Prisma models, especially those with timestamp fields and frequent chronological queries bound to foreign keys, explicitly verify that composite indexes like `@@index([foreignKeyId, timestampField])` are present in `schema.prisma` to prevent performance bottlenecks as data scales.
