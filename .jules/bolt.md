## 2025-02-12 - Missing Prisma Foreign Key and Sorting Indexes
**Learning:** Prisma does not automatically index foreign key columns (like `userId`) in PostgreSQL, which requires manual addition of `@@index` in `schema.prisma`. Furthermore, common query patterns that filter by a foreign key and sort by a timestamp (e.g., `orderBy: { at: 'desc' }`) can be significantly optimized. B-Tree composite indexes (e.g., `@@index([childId, at])`) naturally support `ORDER BY ... DESC` queries without needing an explicit `sort: Desc` declaration in the schema, preventing expensive in-memory sorts.
**Action:** Always explicitly verify the query access patterns (filtering + sorting) and ensure that foreign keys and sort columns have appropriate composite indexes in `prisma/schema.prisma` to support fast retrieval and prevent full table scans.
