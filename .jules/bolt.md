## 2025-02-28 - Missing composite indexes in Prisma models queried chronologically
**Learning:** In the Prisma schema for this application, several models (e.g. ChildProfile, ParentalApproval, ParentalActivity, and Session) are heavily queried using specific foreign keys (like parentId, childId, or userId) and sorted by a timestamp in descending order (e.g., createdAt(sort: Desc), at(sort: Desc), or lastUsedAt(sort: Desc)). The lack of composite indexes for these combinations forces database-level sorting (which degrades performance on large tables) instead of utilizing an index.
**Action:** Add composite indexes on the heavily queried foreign keys and timestamp sort column (specifying (sort: Desc)) to the Prisma schema using @@index([foreignKey, timestamp(sort: Desc)]) along with an explicit @performance comment, and write a matching SQL migration.
