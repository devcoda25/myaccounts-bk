## 2025-02-27 - [Missing Sorting Indexes on Frequently Queried Chronological Fields]
**Learning:** Prisma's default querying pattern for nested reads and lists often involves filtering by a parent ID (`userId`, `childId`, `parentId`) and sorting chronologically (`at` desc, `createdAt` desc). Without explicit composite indexes specifying the exact sort direction (`@@index([childId, at(sort: Desc)])`), the database must perform expensive in-memory sorts (e.g., using a single-field index on `childId` then sorting the rows). This becomes a severe bottleneck as user activity grows, particularly for audit logs, sessions, support tickets, and parental activities.
**Action:** Always verify if heavily queried list endpoints (like `findManyByChildId` or `findUserTickets`) enforce sorting. If so, add a composite index covering both the filter ID and the sorted field with the `(sort: Desc)` directive in the Prisma schema.
