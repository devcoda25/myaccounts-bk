## 2025-02-27 - Database Query Optimization: Composite Indexes for Sorting
**Learning:** Models like `ParentalActivity`, `ParentalApproval`, and `Notification` are frequently queried by their parent ID (e.g., `childId` or `userId`) and strictly ordered by a chronological field descending (e.g., `at` or `createdAt`). Without a composite index matching this exact query pattern, the database must perform expensive in-memory sorts after filtering. While simple indexes on the foreign key help filtering, they do not optimize the sort phase.
**Action:** Always inspect the `orderBy` clauses in repository `findMany` methods (e.g., `findManyByChildId`). If sorting descending is common, add a composite index declaring the sort direction in Prisma (e.g., `@@index([childId, at(sort: Desc)])`) to allow the database to return pre-sorted results and avoid costly `filesort` operations.
