## 2024-03-25 - [Missing Composite Indexes for Sort Queries]
**Learning:** In this Prisma + PostgreSQL codebase, there are widespread access patterns that filter by a parent's foreign key (`userId`, `childId`) and sort descending by a timestamp (`createdAt`, `at`, `lastUsedAt`), like fetching a user's latest sessions or a child's recent activities. While single-column indexes exist for the foreign keys or timestamps independently, the absence of composite indexes (e.g., `[userId, createdAt]`) forces the database to perform costly in-memory sorts (FileSort) after retrieving the filtered records, which degrades performance significantly as tables grow.
**Action:** When adding or reviewing models with common "latest items for parent" access patterns, explicitly create B-Tree composite indexes like `@@index([parentId, timestampField])` to allow the database to return pre-sorted results without an explicit sort step.
