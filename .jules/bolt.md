## 2024-05-24 - Missing Composite Indexes for Chronological Sorts in PostgreSQL/Prisma
**Learning:** Prisma does not automatically index foreign key columns in PostgreSQL, and standard indexes do not cover sorting well enough. A common query pattern in this codebase involves filtering by a user-related ID (e.g., `userId`, `childId`) and sorting by a timestamp (e.g., `createdAt`, `at`, `lastUsedAt`), which necessitates composite indexes (e.g., `@@index([userId, createdAt])`) to prevent expensive in-memory filesorts. B-Tree composite indexes naturally support `ORDER BY ... DESC` queries.
**Action:** When inspecting Prisma schemas for performance optimizations in PostgreSQL, proactively check for missing composite indexes on models that are frequently queried by a foreign key and then sorted chronologically. Add them to support common access patterns and avoid in-memory sorts.
