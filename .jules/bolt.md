## 2024-05-24 - [Database Performance: Missing Composite Indexes on Chronological Queries]
**Learning:** This codebase relies heavily on chronological queries (sorting by `at` or `createdAt` descending) filtered by related entity IDs (e.g. `childId`, `parentId`, `userId`). In PostgreSQL, B-Tree indexes naturally support `ORDER BY ... DESC` but Prisma does not automatically generate indexes for foreign keys or sorts. Without explicit composite indexes like `@@index([childId, at])`, queries run the risk of expensive in-memory filesorts. B-tree indexes natively support `DESC` sorting, avoiding the need to append `sort: Desc` within the schema declaration.
**Action:** When creating new models or query access patterns that involve sorting chronologically by a foreign key, ensure you proactively include a composite index covering both fields in `prisma/schema.prisma`.
