## 2025-02-23 - [Prisma Composite Indexes for Chronological Queries]
**Learning:** In Prisma with PostgreSQL, when using common query patterns that filter by a foreign key (e.g., `userId`, `childId`) and sort by a chronological field (e.g., `createdAt`, `at`, `lastUsedAt`), a single column index is insufficient. This access pattern can result in an expensive in-memory sort unless a composite index `@@index([foreignKey, chronologicalField])` is present. Prisma does not automatically index foreign keys, let alone composite keys for sorting.
**Action:** When creating or optimizing models in `prisma/schema.prisma` that undergo chronological querying filtered by a relation ID (such as `findManyByParentId`, `findManyByChildId`, `findUserTickets`), always explicitly define a composite index on `[relationId, timeField]` to improve performance and avoid expensive in-memory filesorts.
