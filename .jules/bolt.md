## 2026-04-03 - [Missing Composite Indexes for Chronological Queries]
**Learning:** Common query patterns in this codebase filter by an ID (e.g., `userId`, `childId`, `parentId`) and sort by a timestamp (`createdAt`, `lastUsedAt`, `at`) using `orderBy: { <field>: 'desc' }`. Prisma and PostgreSQL without composite indexes will perform expensive in-memory sorts for these queries, leading to N+1-like performance degradation on large datasets.
**Action:** Always check `schema.prisma` for `@@index([<foreignKey>, <timestampField>])` when encountering chronological `findMany` queries. For instance, `ChildProfile.findManyByParentId` relies on `@@index([parentId, createdAt])`. We should explicitly add these to other models exhibiting the same query pattern, like `Session`, `Notification`, `SecurityReport`, `SupportTicket`, `ParentalApproval`, and `ParentalActivity`.
